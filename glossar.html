Glossar · App-Entwicklung

Glossar: App-Begriffe, einfach erklärt.

Wer eine App entwickeln lässt, stößt auf viele Fachwörter. In diesem Glossar sind die App-Begriffe dieser Website einfach erklärt, jeder in ein bis zwei Sätzen. Dazu steht hier, welches Paket hinter welchem Backnamen steckt.

Von A bis Z

Begriffe der App-Entwicklung.

Die Erklärungen sind bewusst kurz. Was ein Begriff für Ihr Vorhaben bedeutet, klären wir im Erstgespräch.

Abhängigkeit
Fremder Programmcode, den eine App mitbenutzt, etwa für Karten oder Zahlungen. Veraltet eine Abhängigkeit, braucht die App ein Update.
API
Kurz für Application Programming Interface, das englische Wort für Schnittstelle. Über eine API stellt ein Programm Daten oder Funktionen bereit, die andere Programme nutzen können.
Backend
Der Teil einer App, der auf einem Server läuft: Er speichert Daten, verwaltet Konten und hält mehrere Geräte auf demselben Stand. Was Nutzer auf dem Handy sehen, heißt Frontend.
Bibliothek
Ein Paket fertigen Codes für eine bestimmte Aufgabe, etwa für Diagramme oder die Anmeldung. Jede Bibliothek, die eine App nutzt, ist eine ihrer Abhängigkeiten.
Bugfix
Die Behebung eines Programmfehlers. Der Bug ist der Fehler, der Fix seine Korrektur.
Code-Review
Ein zweiter Blick auf geschriebenen Code, bevor er übernommen wird: Ist er verständlich, sicher und tut er, was er soll?
Codebasis
Der gesamte Programmcode einer App. Native Apps für iOS und Android haben zwei Codebasen, plattformübergreifende Apps teilen sich eine ganz oder teilweise.
Datenmodell
Der Plan, welche Daten eine App speichert und wie sie zusammenhängen, etwa Nutzer, Termine und Buchungen.
Feedbackschleife
Eine Runde, in der Testerinnen und Tester eine Version ausprobieren. Ihre Rückmeldungen fließen in die nächste Version ein.
Firebase und Supabase
Zwei Dienste, die ein fertiges Backend bereitstellen, mit Anmeldung, Datenbank und Zugriffsregeln. Firebase gehört zu Google, Supabase setzt auf die Datenbank PostgreSQL.
Framework
Ein Grundgerüst aus fertigem Code, auf dem eine App aufsetzt. Flutter und React Native sind Frameworks, mit denen eine App für iOS und Android aus einer Codebasis entsteht.
Git-Repository
Der Ablageort des Programmcodes. Git hält jede Änderung mit Datum und Verfasser fest, so lässt sich jeder frühere Stand wiederherstellen.
GMP
Good Manufacturing Practice, auf Deutsch gute Herstellungspraxis: Regeln für die Herstellung etwa von Arzneimitteln. Jeder Schritt wird dokumentiert, geprüft und freigegeben.
Klickbarer Prototyp
Ein Modell der App aus gestalteten Bildschirmen, durch das man sich klicken kann, noch ohne Programmcode. Oft Klickdummy genannt.
Lauffähiger Prototyp
Ein erstes Stück echter Software mit Code. Es beantwortet eine technische Frage, etwa ob eine Schnittstelle die nötigen Daten liefert.
MVP
Minimum Viable Product: die erste Version einer App, die echte Nutzer verwenden können, mit nur den wichtigsten Funktionen. Mit ihr zeigt sich, ob die Idee trägt.
Nativ
Eine native App ist mit der Sprache und den Werkzeugen ihres Systems entwickelt: Swift für iOS, Kotlin für Android. Sie kann alle Funktionen des Geräts nutzen.
OS-Version
Die Version des Betriebssystems (englisch Operating System, kurz OS), also von iOS oder Android. Apple und Google bringen jedes Jahr eine neue heraus, und Apps müssen Schritt halten.
Plattformübergreifend
Eine App für iOS und Android aus einer ganz oder teilweise gemeinsamen Codebasis, etwa mit Flutter, React Native oder Kotlin Multiplatform.
PoC
Proof of Concept, auf Deutsch Machbarkeitsnachweis: Eine kleine, lauffähige Umsetzung zeigt, ob eine technische Idee funktioniert, bevor viel Geld hineinfließt.
Progressive Web-App
Eine Web-App, die sich wie eine App auf den Home-Bildschirm legen lässt. Kurz PWA.
Pull Request
Ein Vorschlag für eine Änderung am Code, der erst geprüft und dann übernommen wird. So bleibt jede Änderung nachvollziehbar.
Release
Die Veröffentlichung einer neuen Version, etwa im App Store oder bei Google Play.
Schnittstelle
Ein festgelegter Weg, über den zwei Programme Daten austauschen, etwa eine App und ein Kassensystem. Oft API genannt.
Serverseitig
Auf dem Server, außerhalb des Geräts der Nutzer. Eine Prüfung, die serverseitig läuft, lässt sich am eigenen Gerät nicht umgehen.
Sprint
Ein kurzer Arbeitsabschnitt mit einem festen Ziel, meist ein bis zwei Wochen lang.
TestFlight
Apples Dienst für Testversionen: Tester installieren darüber eine App auf dem iPhone, bevor sie im App Store erscheint. Bei Google Play heißt das Gegenstück interner oder geschlossener Test.
Ticket
Eine beschriebene Aufgabe in der Entwicklung, etwa eine neue Funktion oder ein Fehler. Auch Issue genannt.
Unit-Test und UI-Test
Automatische Prüfungen. Ein Unit-Test prüft einen kleinen Baustein des Codes, ein UI-Test bedient die Oberfläche der App (User Interface, kurz UI) wie ein Nutzer.
Web-App
Eine Anwendung, die im Browser läuft. Sie braucht weder Store noch Installation, ein Link genügt.
Wireframe
Eine schlichte Skizze eines Bildschirms ohne Farben und Bilder. Sie zeigt, wo was hingehört.
Zugriffsregeln
Regeln im Backend, die festlegen, wer welche Daten lesen und ändern darf. Ohne solche Regeln können Daten für Fremde einsehbar sein.
